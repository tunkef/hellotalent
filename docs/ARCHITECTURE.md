## 1. Tech Stack & Hosting

Vanilla HTML/CSS/JS frontend (no framework, no bundler) backed by Supabase (PostgreSQL + Auth + Storage + RLS + Edge Functions). Hosted on GitHub Pages at `hellotalent.ai` with Cloudflare DNS/CDN in front. Repo: `github.com/tunkef/hellotalent`. All JS uses `var` (not const/let) in profil.html and ik.html for Safari compatibility. New features are wrapped in IIFEs; cross-file sharing via `window._htFunctionName`.

## 3. Panel Routing Sistemi

- **Hash-based routing**: `#merkez`, `#ayarlar`, `#kimbakti`, `#mulakat`, etc.
- **`switchPanel(panelKey)`**: defined in `profil-wizard.js`, called by helpers/events/genel/inbox + inline delegation.
- **Lazy-load pattern**: feature modules expose `window._htLoadXxx()` loaders (e.g., `window._htLoadStudio()`). `switchPanel` calls the loader on first visit, subsequent visits reuse cached DOM.
- **Bootstrap sync**: `profil-bootstrap.js` sets `window._htBootstrapDone = true` and dispatches `ht:bootstrap-done` custom event. `profil-events.js` waits for this event before restoring hash from URL (fixes 300ms race condition).

### RLS Pattern

- Candidate CRUD: `{table}_select_own`, `{table}_insert_own` using `get_my_candidate_id()`
- Employer read: `{table}_employer_read` using `is_employer()` helper
- Child table RLS: always checks parent candidate `is_active` + `profile_completed`
- Coach: own rows + admin all + authenticated read published

## 7. Auth Flow

```
giris.html (login page)
  ├── Candidate tab → Supabase Auth → profil.html
  └── IK tab → Supabase Auth → ik.html (user_metadata.role === 'employer')

gate.html → sessionStorage gate for content pages
Legal pages (gizlilik, kvkk, kullanim-sartlari, cerez-politikasi) → no gate

account_status enum: active → frozen → pending_deletion
  - frozen/pending_deletion → is_active = false (trigger: sync_account_status_to_active)
  - Login allowed for frozen/pending_deletion (self-recovery)
  - KVKK md.11: 30-day grace → cron purge
```

Cross-role prevention in giris.html (candidate cannot access ik.html, vice versa).

## 8. Email Pipeline

### Architecture

```
[DB trigger / RPC] → email_outbox (pending)
                          ↓
               email-send Edge Function (pg_cron every 1 min)
                          ↓
                    Resend API → recipient
```

- `email-reconcile` cron (every 5 min): enqueues welcome emails by scanning new auth users
- `email-send` cron (every 1 min): claims pending rows, sends via Resend, marks sent/failed
- `auto_close_resolved_tickets()`: pg_cron daily at 03:00 UTC

### Email Types (CHECK constraint, 10 types)

`candidate_welcome`, `employer_welcome`, `new_message`, `support_ticket_confirmation`, `support_ticket_internal_alert`, `support_ticket_resolved`, `support_ticket_admin_reply`, `support_ticket_candidate_reply`, `support_ticket_auto_closed`, `coach_post_archived` (+ coach notification types: `coach_post_published`, `coach_post_changes_requested`, `coach_post_rejected`, `deletion_requested`, `deletion_dismissed`)

### Status Flow

`pending` -> `processing` -> `sent` (success) or `failed` (retry with backoff)

Provider: Resend API. Env vars: `RESEND_API_KEY`, `EMAIL_FROM`, `REPLY_TO`.

## 9. AI Feedback Pipeline

### Architecture

```
Candidate clicks "AI ile Degerlendir"
  → request_journal_feedback RPC (upserts journal, creates pending row)
  → journal-feedback Edge Function (pg_cron trigger)
      → Claims pending rows (batch up to 5)
      → Calls OpenAI gpt-4.1-mini with structured Turkish prompt
      → Forces response_format: json_object
      → complete_journal_feedback RPC (writes structured result)
  → Client polls get_journal_feedback every 1s, 75s timeout
  → Result: signal pill + score + STAR+T analysis + accordions
```

### Premium Gating

- `S.isPremium` check (currently hardcoded false, awaits real subscription)
- Non-premium: gate card "AI Koc degerlendirmesi Premium ozelligidir" + "Premium'a Gec" CTA
- Free users can still use journal drafting fully

### Feedback Schema

`candidate_journal_feedback`: `status` (pending/processing/completed/failed), `overall_signal` (strong/mixed/needs_work), `score_overall`, `strong_points` (jsonb), `weak_points` (jsonb), `star_review` (jsonb: S/T/A/R/+T status+note), `improvement_actions` (jsonb), `followup_questions` (jsonb), `summary_text`
